工作台

与外部 Agent 配合的分镜工作台：Agent 写分镜、写视频提示词、备资产；工作台在单页画布上把它们的关系统统连起来，让你看清写了什么、一键复制、随手批注，并核对资产是否就绪。

当前版本是审阅工具，不是生成工具。整个界面只有一页：中间是节点画布，用连线摊开批次、场、镜、提示词与资产的关系；右侧是预览面板，选中什么就读什么。它管理两条并行的资产线：外部 Agent 写下的「视频提示词」，以及提示词槽位引用的人物 / 场景 / 道具「参考资产」。提示词一键复制、浮动便签随手记；资产按主体看就绪与缺失。软件绝不改写原稿——所有修改回到 Agent，通过审阅意见闭环。
01

定位与问题

1.1 生产链路中的位置

剧本→ 分镜脚本（21 字段）→ 视频提示词（逐镜）→ 参考图 / 素材→ 工作台：看、核、批

前四步由外部 Agent 完成。工作台不参与创作，只把已经写下的内容变成可审阅的形态。

之所以需要它：分镜脚本是一张 21 列的宽表，视频提示词是另一批分散文件。Agent 能写得很快，但人很难在宽表里看出节奏、在几十个文件里发现哪一镜漏了提示词。审阅成本远高于生成成本。

1.2 四个具体问题

问题表现后果
宽表看不出节奏21 列里时长、景别、节拍分散在不同列；总时长、平均镜长、景别配比要手工算。节奏问题要等剪出来才发现，返工成本高。
提示词与镜头脱节视频提示词是独立文件，镜号写错、漏写、引用了不存在的角色，都不会报错。跑片时才发现缺图或缺提示词，且不知道是哪一镜。
资产与槽位对不上角色四视图、场景图、道具图散在资产目录，提示词却只写 <Subject 1>。跑到某一镜才发现参考图没准备，或主体名根本对不上。
审阅意见不可执行口头说「第 12 镜节奏慢」，Agent 无法定位到字段与改法。反复来回，改稿靠猜。

1.3 目标（可观察结果）

  • 看得见时长：打开一集，镜头按真实时长铺开，总时长与平均镜长直接显示。
  • 看得见原文：任意一镜可展开 21 个字段的原始文字与视频提示词全文，不做改写、不做摘要。
  • 看得见问题：字段缺失、镜号断号、台词超时、提示词缺失或错位，逐镜标红并可跳转。
  • 分得开批次：按 01 / 02 / 03 段落批次逐个查看，不必一次面对整集几十镜。
  • 拿得走：任意一镜的提示词正文一键复制，直接粘给生成平台或 Agent。
  • 记得下：浮动便签随手写「这里要改什么」，自动跟随当前镜，事后再转成审阅意见。
  • 对得上资产：提示词里 <Subject N> / <Picture N> 引用的角色、场景、道具，能看到是否就绪、被哪些镜引用、缺了哪些。
  • 一张画布看全：单页面 + 节点画布，把批次、场、镜、提示词、资产的关系用连线摊开，点节点即在右侧读全文。
  • 批得下去：每条意见带镜号、字段、问题、改法，可导出给 Agent 直接执行。

02

范围

2.1 P0：最小完整旅程

环节定义
入口条件外部 Agent 已产出一集的分镜脚本（Markdown 表，21 字段）与逐镜视频提示词文件。
完成动作导入一集 → 在单页画布上按批次看节点 → 点节点在右侧预览 21 字段与提示词 → 复制需要的提示词 → 便签贴到节点上记下修改点 → 导出审阅意见。
完成证据屏幕上能回答四个问题：这一集多长、这一批有哪些镜、哪几镜有问题、每一镜到底写了什么；且已把要改的点记在便签里并导出。
恢复路径分镜表缺列或格式异常 → 保留原文并指出无法解析的行列，允许「按原表查看」；单镜提示词缺失 → 标为问题，不影响其余镜。

2.2 P1 支撑

资产管理不是附属卡片：提示词里的槽位引用的就是这些资产，资产缺失会让提示词悬空。因此资产管理与提示词管理并列，作为一个完整功能域（4.6）。

资产看板

按角色 / 场景 / 道具 / 音频分组，显示参考图是否就绪。

槽位引用映射

每一镜的 Subject / Picture 槽位指向哪个资产，一目了然。

缺资产清单

按镜号与主体列出缺失项，一键导出给 Agent 补图。

静帧与参考图

镜卡显示已生成的参考图或首帧，缺失时显示占位。

连播 animatic

按每镜时长把静帧连起来播放，检查节奏与停顿。

版本对比

Agent 改稿后重新导入，逐镜对比字段与提示词的变化。

门禁报告集成

读取外部 Agent 的评分、可拍摄性、合规结论，显示在集级状态栏。

原表导出

按原 21 列导出 Markdown / CSV / PDF，供打印与交组。

2.3 不做

不做原因
在软件里编辑分镜或提示词会形成第二份真相。软件只读、批注，改稿权在 Agent。
从剧本自动拆解分镜拆解是 Agent 的职责；软件若参与，审阅就失去独立性。
节点级生成（本轮不做）本轮只做审阅面，生成任务由 Agent 调度。v2.5 起以「节点级试生成」接入，且结果只落资产层、不回写分镜与提示词（见 10 路线图 ④）。
3D 预演 / 运镜仿真成本极高，且当前要解决的是「核对文字」，不是「预演画面」。
多用户协同与评论线程单人审阅，先保证闭环，不做协作系统。
03

数据模型

3.1 对象

对象定义关键属性来源
项目 Project一部作品的容器。名称、画幅、目标时长、平台目录与配置
集 Episode一次审阅的单位，对应一份分镜表。序号、标题、目标时长、总时长分镜表头 + 计算
批次 Batch集内按段落序号（01 / 02 / 03）划分的连续镜号区间，是分阶段预览的默认单位。批次号、标题、起止镜号、镜数、时长分镜.meta.json 的 batches；缺失时回退到按场次
场 Scene同一时空的一段戏，由镜号的场次前缀聚合。场次号、内外、日夜、镜数、时长由镜号与场次字段推导
镜 Shot审阅的最小单位，承载 21 字段。镜号、21 字段、审阅状态、问题列表分镜表数据行
视频提示词 Prompt P0 核心资产该镜交给视频模型的完整描述，是本软件真正要管理、预览与复制的对象。镜号、prompt、negative、参数、主体槽位、图片槽位逐镜独立文件
审阅意见 Note人对某镜某字段的判断与改法。镜号、字段、问题、改法、优先级、状态、来源人工批注 / 自动检查 / 便签转入
浮动便签 StickyNote审阅过程中随手记下的「这里要改什么」，可自动跟随当前镜或手动锁定到某镜。内容、绑定镜号（可空）、锁定状态、创建时间、是否已转意见人工输入，本地持久化
资产 Asset角色 / 场景 / 道具 / 音频的参考素材，是提示词槽位真正指向的东西。主体名、别名、类型、参考图（四视图 / 场景图）、文件路径、就绪状态、被引用次数项目 资产/ 清单与目录
槽位引用 SlotRef提示词中的 <Subject N> / <Picture N> 到资产的一条解析记录。镜号、槽位号、标记类型、解析到的资产、解析状态（已就绪 / 缺失 / 歧义）解析提示词正文与资产清单

3.2 关系

项目1 : N 集1 : N 批次1 : N 场1 : N 镜1 : 1 视频提示词 · 镜1 : N 审阅意见 · 镜0..N 浮动便签 · 镜N : N 资产 · 提示词槽位N : 1 资产

镜号是唯一的连接键：分镜表、视频提示词、审阅意见、浮动便签、资产关联全部按 SC03-SH012 对齐。批次只是镜号上的一层可视分组，不额外引入新键；槽位引用把「提示词」与「资产」接起来。

3.4 镜的审阅状态

未读→ 已读→ 有问题→ 已确认

自动检查产生的问题不会改变状态，只有人逐镜确认或标问题才推进。状态只存在索引，不写回分镜表。

04

功能需求

4.1 导入与解析

FR-01

项目与集导入

目的把 Agent 产出的分镜表与提示词文件接入，不需要手工复制粘贴。
触发首次选择一个项目目录；或点击「导入 / 刷新」。
处理规则
  • 识别一集的结构：分镜主表（.md 或 .json）与逐镜提示词目录。
  • 同一集同时存在 JSON 与 Markdown 时，以 JSON 为准并提示两者不一致的镜号。
  • 导入只读，不移动、不改写 Agent 的文件。
  • 支持多个集并列，按集序号排序。
结果与状态集出现在左侧列表，显示镜数、总时长、问题数、审阅进度。
异常表头不是 21 字段、缺少镜号列、编码非 UTF-8 → 拒绝解析并指出具体行；原文仍可按纯文本查看。
FR-02

分镜表解析

目的把宽表还原成结构化的镜，且不丢任何一个字。
触发导入或文件变更时自动执行。
处理规则
  • 按表头名称匹配 21 个字段，允许顺序不同、允许缺列（缺列记为缺失并报警）。
  • 数据行以镜号开头；识别 SC01-SH001 及 -R1 / -A 变体。
  • 单元格保留原文（含换行与标点），不做 trim 以外的清洗。
  • 空单元格与 — 视为「无内容」，但仍在详情中原样展示。
结果与状态每镜生成结构化记录；解析警告按行号汇总。
异常合并单元格、表格断行、一格里塞了多镜 → 标「结构异常」，该行不进时间轴，但可在原表中看到。

4.2 时间轴与镜卡

FR-03

时间轴渲染

目的让节奏变成可见的宽度，而不是 21 列里的一个数字。
触发常驻单页顶部；切换集、批次或画布筛选时重算。
处理规则
  • 镜头块宽度与 dur 成正比，同一集共用一条时间尺度；可折叠成细条以让位给画布。
  • 按场次分段，场与场之间留间隔并标注场次名与场内时长。
  • 块内显示镜号、景别、时长；可按节拍或景别切换配色。
  • 有问题或未解决的镜在块右上角标红点。
  • 顶部显示：镜数、总时长、平均镜长、目标时长偏差、问题数。
  • 与画布双向联动：点镜头块选中对应画布节点，点画布镜节点高亮对应镜头块。
结果与状态点击镜头块选中该镜并同步右侧预览面板；键盘左右键逐镜移动。
异常时长为空或非数字 → 该块用最小宽度并标红，不参与总时长计算（单独列出「缺时长」）。
FR-04

预览面板：镜卡检查器（写了什么）

目的回答「这一镜到底写了什么」，一字不改地呈现原稿。
触发在画布、时间轴条或场次抽屉中选中一镜。
处理规则
  • 按 21 字段顺序展示，字段名与分镜表一致；空值显示「—」。
  • 长文本（画面内容、台词、备注）完整展开，不截断、不折叠。
  • 提供「原表行」视图：显示该镜在 Markdown 中的原始一行，可对照。
  • 字段缺失或格式可疑时，在字段旁标注而不是替换内容。
结果与状态面板内容与选中节点严格同步；切换节点不丢失滚动位置以外的一切状态。
异常字段内容含表格分隔符或非法字符 → 原样显示并标「需回源核对」。
FR-05

提示词预览、分批次与一键复制

目的逐镜确认提示词写了什么、有没有写、写没写错镜号，并能立刻把正文拿去用。
触发选中画布上的提示词节点；或在预览面板切到「提示词」tab；或点击批次条切换批次。
处理规则
  • 画布节点 + 面板全文：提示词在画布上是节点（标题、字数、槽位数与复制入口），选中后在预览面板读全文。
  • 分批次预览：按批次（01 / 02 / 03 段落序号）分组，画布默认只铺开当前批次的节点；批次条显示批次号、标题、镜数、时长与问题数，可前后翻批或「看全部」。
  • 批次元数据优先读 分镜.meta.json 的 batches；缺失时按场次分批，并在批次条上明确标注「未配置批次，按场次暂分」。
  • 批次内按镜号顺序连续排列，每一镜显示 prompt 全文、negative、主体槽位、图片槽位与参数；长文本完整展开。
  • 一键复制：每张提示词卡右上角固定一个复制按钮。默认复制「纯 prompt 正文」；下拉可选「含负面提示词」「含参数」「完整 frontmatter 文件」。复制后按钮短暂反馈「已复制」。
  • 批次级提供「复制本批全部」：按镜号顺序拼接为纯文本，镜号作为分隔标题，便于整批粘给 Agent。
  • 提示词只读，不提供编辑；正文中引用的 <Subject N> / <Picture N> 高亮。
结果与状态有提示词的镜显示摘要与复制入口；无提示词的镜明确标「未写」，且复制按钮置灰。
异常文件存在但镜号不匹配 → 列为「疑似错位」，同时展示文件镜号与实际内容，由人判断；批次区间存在缺口镜号 → 批次条标「含断号」，仍可预览但不补齐。

4.3 核对与审阅

FR-06

完整性检查

目的在开跑前拦住「字段没填」这类低级但致命的问题。
触发导入后自动执行，随编辑外的文件变更重算。
处理规则
  • 检查 14 个必填字段是否为空或占位：「画面」占位、「待补」「TBD」「略」均视为未写完。
  • 检查镜号是否连续、是否重号、场次前缀与场次字段是否一致。
  • 检查素材编号是否符合 A{场次}_{镜序} 且与镜号一一对应。
  • 问题按镜号聚合，不生成笼统的「整集有问题」。
结果与状态每镜的问题数显示在时间轴与检查器；顶部汇总为问题清单。
异常整集无有效数据行 → 提示「未解析到分镜」，并给出表头检查建议。
FR-07

结构与节奏检查

目的把原本要手工算的时长与配比变成常驻结论。
触发导入后自动执行。
处理规则
  • 单镜时长超出 0.5–4.0s → 标警告。
  • 台词字数 ÷ 5.0 与 dur × 0.9 比较，超出即「念不完」。
  • 全场时长合计与场次标注偏差 >5% → 标警告；全集与目标时长偏差 >3% → 标警告。
  • 景别配比：特写组（ECU/INS/CU）35–45%、中景组（MCU/MS）30–40%、中全景组（MFS/FS）15–25%、远景组（LS/ELS）≤10%。
  • 连续同景别超过 4 镜、连续同节拍超过 4 镜 → 标节奏警告。
  • 画面/动作栏出现「并且 / 同时 / 然后」→ 提示「可能需拆镜」，不自动判定。
结果与状态节奏结论以条形与数字呈现，不写成「节奏偏慢」这类不可证伪的话。
异常缺失时长导致无法计算时，明确标「数据不足」，不给假结论。
FR-08

提示词一致性检查

目的保证「每一镜都有提示词，且提示词对得上这一镜」。
触发导入后自动执行。
处理规则
  • 分镜有镜、无提示词 → 「缺提示词」。
  • 有提示词文件、镜号找不到 → 「孤儿提示词」。
  • 提示词声明的镜号与文件名不一致 → 「疑似错位」。
  • 正文引用了未声明的槽位 → 「引用悬空」。
  • 槽位引用的主体在素材库中不存在 → 「主体未建」（素材库接入后生效）。
结果与状态问题逐镜挂载；「孤儿提示词」单独成列，不混进镜列表。
异常提示词文件编码或格式损坏 → 保留文件路径并标「无法解析」，不猜测内容。
FR-09

审阅标记与问题清单

目的让审阅有进度、有结论，而不是看完就忘。
触发人点击「确认」或「标问题」；自动检查产生的问题默认待处理。
处理规则
  • 每镜状态：未读 / 已读 / 有问题 / 已确认。
  • 问题可手写，字段：镜号、字段、问题、改法、优先级（P0/P1/P2）。
  • 浮动便签可一键「转为审阅意见」：自动带入绑定的镜号与便签原文，人补齐字段与改法后入清单；未绑定镜号的便签转入时要求先选镜。
  • 每条意见记录来源：自动检查 / 人工批注 / 便签转入，导出时一并保留。
  • 自动问题可被人工「忽略」，忽略需填原因，避免反复弹同一提示。
  • 问题清单可按场次、优先级、字段筛选。
结果与状态集列表显示审阅进度（已确认 / 总镜数）与未解决 P0 数量。
异常重新导入后镜号消失 → 相关意见标「镜已删除」，不静默丢弃。

4.4 意见回传与支撑

FR-10

审阅意见导出

目的把审阅结果变成 Agent 能直接执行的指令。
触发点击「导出审阅意见」。
处理规则
  • 按镜号分组输出 Markdown：每条含优先级、字段、可证伪的问题、可落笔的改法、来源。
  • 同时输出机器可读 JSON，字段与问题清单一致。
  • 可只导出未解决项，或包含已忽略项与原因。
  • 导出文件写到项目目录，不覆盖 Agent 原稿。
结果与状态导出后意见状态标「已反馈」，等待下一版分镜。
异常没有未解决项 → 明确提示「无需反馈」，不生成空文件。
FR-11

参考帧与素材就绪（P1）

目的在镜卡上直接看到这一镜要用的角色/场景图是否就绪。
触发素材库已接入且提示词声明了图片槽位。
处理规则
  • 按槽位解析出主体与角色标签，匹配素材库中的资产。
  • 就绪 → 显示缩略图；缺失 → 显示占位与「缺素材」标记。
  • 只读展示，不在工作台里入库或替换素材。
结果与状态镜卡出现参考图区；集级显示素材就绪率。
异常素材库未接入 → 整个区块隐藏，不显示 0% 这类误导数字。
FR-12

版本对比与门禁报告（P1）

目的Agent 改稿后，快速确认「改了哪几镜、改成什么」。
触发同一集导入新版本；或项目目录下存在门禁报告文件。
处理规则
  • 按镜号对比字段与提示词，标出新增、删除、修改的镜与字段。
  • 门禁报告（评分 / 可拍摄性 / 合规）只在集级展示结论与不通过项，不重新计算。
  • 对比结果只读，不合并、不自动接受。
结果与状态版本差异列表可逐条跳转到对应镜。
异常镜号大量变动导致无法对齐 → 退化为「整表替换」，并提示可能不是同一集。

4.5 提示词资产与随手批注

FR-13

提示词资产库

目的把散落在 video/ 里的提示词收成一份可检索、可定位、可复制的清单，而不是靠翻文件夹。
触发打开「提示词」视图，或点击集级「提示词资产库」。
处理规则
  • 列表字段：镜号、所属批次、景别、时长、提示词字数、槽位引用数、是否已写、问题数。
  • 支持按批次、场次、状态（已写 / 未写 / 疑似错位 / 无法解析）筛选，支持正文全文搜索。
  • 行内可直接复制纯 prompt 正文，复制规则与 FR-05 一致；点击行跳转到该镜在画布上的节点。
  • 清单只索引文件内容，不复制、不缓存成第二份可编辑副本。
结果与状态未写提示词的镜在列表顶部单独分组，可一键把镜号清单发给 Agent。
异常文件被外部改动 → 下次刷新时重算索引，并保留已有人工便签与意见。
FR-14

浮动便签

目的审阅时想到「这一镜要改」，不必打断浏览去填表单，随手记下且不丢。
触发全局快捷键或浮动按钮唤出；可常驻在窗口右下角。
处理规则
  • 跟随模式（默认）：便签标题自动显示当前选中镜的镜号；切换镜时，新输入的内容落到新镜上。
  • 锁定模式：点击图钉把便签锁定到指定镜，之后切换镜不影响；再次点击解除锁定回到跟随模式。
  • 便签可拖动、可折叠成一个小标签、可置顶；不遮挡画布节点标签与预览面板的复制按钮。
  • 每条便签自动保存到本地索引，关闭窗口与重新导入都不丢失；支持多条并存，按镜号倒序查看。
  • 提供「转为审阅意见」与「导出全部便签」；导出格式与审阅意见 Markdown 兼容。
  • 便签内容属于人，不写回分镜表与提示词文件。
结果与状态未转意见的便签以角标计数显示在镜块与集列表上；转为意见后标记「已转」并保留原文。
异常便签绑定的镜在重新导入后被删除 → 便签保留为「未绑定」，提示重新指定镜号；未绑定便签不进入自动导出，除非人确认。

4.6 资产管理（P1）

资产管理是独立功能域：它回答「这一集提示词要用的人、景、物，素材齐不齐」。软件不生产素材，只把 Agent 的资产清单与目录对齐成可核对的看板。

FR-15

资产看板与就绪状态

目的在开机前看清哪些角色 / 场景 / 道具已有参考图、哪些还缺，避免跑到某一镜才发现没图。
触发打开「资产」视图；或集级点击「资产就绪 18 / 21」。
处理规则
  • 按类型分组：角色 / 场景 / 道具 / 音频；每组显示总数、就绪数、缺失数。
  • 每个资产卡片显示：主体名与别名、参考图缩略图（四视图 / 场景图 / 道具图）、文件路径、就绪状态、被引用镜数。
  • 就绪判定：清单存在该资产且参考图文件可读 → 就绪；仅有清单无文件 → 「缺图」；清单与目录都没有 → 「未建」。
  • 点击资产可展开「引用它的镜」列表，逐条跳转到对应镜与提示词槽位。
  • 只读展示，不在工作台里上传、替换或删除资产文件。
结果与状态集列表与资产视图顶部显示就绪率；缺失资产以红色角标挂在对应镜块上。
异常资产目录不存在或清单为空 → 显示「未接入资产」，不显示 0% 这类误导数字；图片损坏 → 显示占位并标「无法读取」。
FR-16

槽位引用映射与缺资产清单

目的把「提示词里写了 <Subject 1>」和「这个主体到底有没有图」对上，缺什么能直接交给 Agent。
触发导入后自动解析；资产视图或提示词卡上查看。
处理规则
  • 解析每条提示词的 <Subject N> / <Picture N> 与 frontmatter 的 subjects / pictures，生成槽位引用记录。
  • 槽位主体在资产清单中唯一匹配 → 「已就绪」；匹配到多个同名主体 → 「歧义」，列出候选由人选择；无匹配 → 「未建」。
  • 缺资产清单按「镜号 + 槽位 + 主体 + 缺失类型（缺图 / 未建 / 歧义）」输出，可一键导出 Markdown 给 Agent 补图。
  • 资产被引用关系是双向的：从资产看「被哪些镜引用」，从镜看「引用了哪些资产」。
  • 不因资产缺失而修改提示词正文；只标记，不替代。
结果与状态每个槽位有明确的解析状态；缺资产清单与问题清单并列，可分别导出。
异常资产清单里主体名与提示词写法不一致（别名 / 错字）→ 标「疑似同一主体」，人工确认后仅记别名，不改原稿。

画布借用 ComfyUI 的心智模型：节点是一份可读的对象，连线表达「谁属于谁」与「谁引用了谁」。但画布不取代时序——节奏仍由顶部时间轴条表达，画布负责把关系摊开。

核心校验规则

这些规则是工作台存在的主要价值，必须逐条落到具体镜号，不允许输出「整体偏慢」这类无法执行的结论。

检查项判定规则输出
必填缺失14 个必填字段为空，或为「—」以外的占位词（待补 / TBD / 略 / ？）。镜号 + 字段名 + 原文值。
镜号连续同场内 SH 序号从 1 连续递增；重号、跳号、场次前缀不符均报。给出缺失序号与位置。
时长区间单镜 0.5–4.0s；不足或超出均标警告。镜号 + 实际时长 + 建议区间。
台词可念完台词字数 ÷ 5.0 ≤ 时长 × 0.9。镜号 + 字数 + 所需时长 + 超出秒数。
集时长偏差总时长与目标时长偏差 ≤3%；单场偏差 ≤5%。实际 / 目标 / 差值。
景别配比ECU+INS+CU 35–45%；MCU+MS 30–40%；MFS+FS 15–25%；LS+ELS ≤10%。四组实际占比与超标方向。
节奏重复连续同景别 >4 镜，或连续同节拍 >4 镜。起止镜号 + 重复值。
一镜多义画面或动作栏出现「并且 / 同时 / 然后 / 又」。镜号 + 命中词；提示可拆镜，不强制。
批次越界batches 的 from / to 在分镜表中不存在，或区间重叠、跳镜。批次号 + 无效区间 + 缺失镜号。
提示词缺失有镜无对应提示词文件。镜号清单，可一键导出给 Agent。
提示词孤儿提示词文件镜号在分镜表中不存在。文件路径 + 声明的镜号。
提示词错位文件内 no 与文件名镜号不一致。两边的镜号，由人裁决。
引用悬空正文使用 <Picture N> 但槽位未声明；或 <Subject N> 无对应主体。镜号 + 引用标记 + 缺失槽位。
主体未建槽位主体名在资产清单与目录中均不存在（含别名）。镜号 + 主体名 + 引用次数。
资产缺图资产在清单中存在，但参考图文件缺失或不可读。资产名 + 期望路径 + 引用镜号。
主体歧义同一主体名匹配到多个资产（重名或别名冲突）。主体名 + 候选资产列表，由人确认。
不做判断的事 画面好不好、表演是否到位、分镜创意是否成立，这些不进入自动检查。软件只报可证伪的结构问题，审美判断留给人。
